## 2026-09-07 — Anime clip generator ("Create anime from text")

- **Contributor:** Chirag Singla (singlachirag25)
- **What it was:** Public Hugging Face Space — a text prompt goes to an LLM that "art-directs" it into a structured scene description, then a diffusion model renders a ~3-second anime clip; the expanded prompt is shown beside the video. Personal portfolio / demo piece.
- **Stakes:** portfolio / demo (explicit at intake — "portfolio piece", "near-free only").
- **Pattern:** Deterministic pipeline (single structured-output LLM call → `diffusers` render → mp4). No agent. **Held up as chosen** — the pattern was never fought; every course-correction was in execution detail (which models, which LLM backend, where the GPU work runs), not in the architecture.
- **Stack (final):** Gradio 6 on HF Spaces **ZeroGPU**; `diffusers` AnimateDiff — `frankjoshua/toonyou_beta6` (anime SD1.5) + `guoyww/animatediff-motion-adapter-v1-5-2` + `wangfuyun/AnimateLCM` LoRA **fused** (LCMScheduler, ~6 steps); prompt expansion via **Groq's own API** (`groq` SDK, `qwen/qwen3.8-27b`), HF Inference Providers as a fallback behind the same interface; `pydantic` schema; `gradio_client` drives the deployed Space for the golden eval.

### What diverged

- **[app-architect] Intake inventoried the dev machine but didn't turn "16 GB MacBook, no CUDA" into a GPU-execution plan.** The app's core workload is video diffusion; the dev machine cannot run it at target size. Phase 0 (the MVP notebook) was nonetheless scoped to run locally on Apple MPS. Result: ~2 hours burned on hardware limits — `Lightricks/LTX-Video` pulled 26 GB then drove 16 GB of swap and hung; the AnimateLCM LoRA as live peft layers took ~15 min/step and drove 34 GB of swap. The first *useful* Phase-0 signal came only later, on the actual ZeroGPU target. — evidence: Deviations `[phase 0] Local MPS is a marginal prototyping environment for this project`, `[phase 0] Route B (LTX-Video) not evaluated locally`, `[phase 2] Local real-render checkpoint deferred to ZeroGPU`; retro: *"The dev machine couldn't do the work"*, *"Where does GPU work actually run? — should have pinned this at intake and planned Phase 0 for Colab/Kaggle/ZeroGPU, not local MPS"*.

- **[app-architect] The LLM backend was chosen without checking the free-tier's actual size.** Spec named Gemini/Groq; a mid-build request moved it to HF Inference Providers (one HF token, matches the Space); that tier turned out to be ~$0.10/month of credit, which **depleted purely from development iteration** (latency probes + test runs) and started returning `402` for the whole app; final state is Groq's own API (14.4k req/day, free). Three backends for one step. — evidence: Deviations `[phase 1] LLM backend changed from Gemini/Groq → Hugging Face Inference Providers`, `[phase 3] HF Inference free credit depleted → Groq's own API is now the primary backend`; retro: *"'Free' LLM tier wasn't really free"*, *"Pick the LLM backend more carefully — should have checked the HF free-tier size and gone Groq-direct from the start"*.

- **[app-developer / framework.md §5] The MVP-notebook step assumes the local dev environment can run the core flow.** For GPU-heavy generative work on a laptop with no usable GPU, that assumption is false, and the notebook pass yields mostly hardware-limit findings rather than idea-validation findings. app-developer proceeded on local MPS per the phase clarify answers instead of flagging "this phase needs a GPU host" back to app-architect. — evidence: Deviations `[phase 0]` cluster; retro Q3 answer was *"Process was fine"* (the gates weren't the friction — the environment choice was).

- **[app-developer] Two model-integration gotchas cost roughly a full cycle each.** (a) An AnimateDiff LoRA left as *live* `peft` adapter layers is pathologically slow on MPS (ops fall back to CPU every denoise step) — fixed by `load_lora_weights` → `fuse_lora()` → `unload_lora_weights()`. (b) Platform micro-rules: ZeroGPU requires *not* pinning `gradio`/`spaces`/`torch` in `requirements.txt`; `gradio_client`'s kwarg is `token=`, not `hf_token=`. Each surfaced only at run/deploy time. — evidence: Deviations `[phase 2] AnimateLCM LoRA must be FUSED, not kept as live peft layers`, `[phase 4] gradio_client kwarg is token=`, `[phase 4] ZeroGPU compliance` notes; retro: *"Framework/library gotchas — small things that each cost a cycle"*.

- **[release-qa / cross-cutting] The scaffolded CI workflow was a no-op and stayed that way through all four build phases.** `.github/workflows/ci.yml` shipped as `pytest -q || (echo "no tests yet" && exit 0)` with a three-package pip install — it collected **zero** tests (`test_app.py` needs `gradio`+`spaces`, `test_pipeline.py` needs `torch`) and passed green regardless. app-developer added 66 tests across Phases 1-3 but never revisited the scaffold's CI stub; nothing in the phased plan said "wire the real CI gate"; release-qa caught it at the Verify stage. So framework.md §9 ("make Verify unavoidable") was silently not in force for the entire build. — evidence: Deviations `[verify] CI gate was a no-op`; the `|| exit 0` line in the scaffold's `ci.yml`.

- **[framework.md §2 / §9] The repo scaffold ships a deliberately-broken CI placeholder with no forcing function to replace it.** The `|| exit 0` "until Phase 1" comment invites exactly the outcome above. A scaffold that shipped either no CI file, or one that fails loudly until tests exist, plus a checklist/phase-plan item "CI gate actually runs and blocks on failure", would have closed this. — evidence: same as the release-qa item.

- **[cross-cutting] What worked, and is worth not losing.** The **Deviations from spec** section was used heavily — ~18 entries across 5 phases plus a release-qa block — and made this capture straightforward and well-evidenced. The phase gates plus release-qa's independence both paid off (release-qa found the fake CI gate, two unguarded crash paths, and unpinned `transformers`/`diffusers`). The chosen architecture pattern was correct and never worked around. — evidence: the spec's Deviations + `## release-qa findings` sections; retro: *"Process was fine — the gates and checks mostly earned their keep"*.

### Retro notes (contributor's words)

- **Redone / thrown away:** "The LLM backend, twice" (Gemini/Groq spec → HF Inference Providers → Groq's own API); "Local video-model attempts" (LTX-Video 26 GB / swap storm, the live-peft-LoRA path at 15 min/step / 34 GB swap, repeated notebook re-runs on a memory-starved Mac); plus one further unspecified item ("Something else", not elaborated).
- **Didn't see coming:** "The dev machine couldn't do the work" — a 16 GB MacBook can't run video diffusion at target size at all; "'Free' LLM tier wasn't really free" — the ~$0.10/month HF Inference credit was depleted just by dev iteration; "Framework/library gotchas" — peft-on-MPS, the ZeroGPU no-pin rule, the `gradio_client` kwarg name.
- **Process friction:** "Process was fine — the gates and checks mostly earned their keep, e.g. release-qa caught the fake CI gate." (Did *not* report the phase gates or the MVP-notebook gate as heavy; the friction was the environment decision, not the process.)
- **Architect should have:** "Where does GPU work actually run? — should have pinned this at intake and planned Phase 0 for Colab/Kaggle/ZeroGPU, not local MPS, once it knew the machine was a 16 GB Mac." / "Pick the LLM backend more carefully — should have checked the HF free-tier size and gone Groq-direct from the start instead of discovering the $0.10 cap mid-build."

### Would do differently

1. **When the dev machine can't run the app's core workload** (here: a generative-video app on a laptop with no usable GPU), decide the GPU-execution host at intake and scope the MVP-notebook / Phase 0 to run *there*, not locally — otherwise that phase burns time on the environment, not the idea.
2. **When a "free tier" is load-bearing for the architecture**, check the actual quota / credit size during §7a research, not mid-build. "Free" and "free enough to develop against" are different claims.
3. **Make the CI gate a real, named build task.** The scaffold's placeholder CI should fail loudly until tests exist, and "CI runs the test suite and blocks on failure" belongs in the phased plan, not left for release-qa to discover at the end.

**Spec — "Deviations from spec" section, verbatim** (`specs/2026-09-06-anime-clip-generator.md`):

- **[phase 0] Route A base model changed** — spec floated "Animagine XL / anime-SDXL" as the keyframe model. Dropped: the stock AnimateDiff motion adapter is SD1.5-only, and SDXL doesn't fit 16 GB MPS alongside the adapter. Using `frankjoshua/toonyou_beta6` (ungated anime SD1.5). AnimateDiff is effectively one-pass text→video, so the separate "keyframe then animate" step collapsed into a single pipeline call.
- **[phase 0] Route B (LTX-Video) not evaluated locally** — `Lightricks/LTX-Video` is ~26 GB (T5-XXL text encoder + transformer). On the 16 GB MPS dev machine, CPU-offload pushed ~16 GB into swap and the denoise loop hung (killed after >60 min, 0 frames). Also needs `tiktoken` + `protobuf` for its tokenizer. Route B was assessed on documented characteristics instead of a local clip. Not a verdict on LTX-Video — it targets CUDA.
- **[phase 0] Local MPS is a marginal prototyping environment for this project** — video diffusion on 16 GB shared memory: Route A only fits below target size (384×256/12f vs the 512×320/16f goal), and any heavier model swaps. Full-size validation must happen on the real target (HF ZeroGPU) in Phase 2. First run also pulled ~38 GB of models on an unauthenticated HF connection before LTX was cut (26 GB of that was LTX; since freed).
- **[phase 0] Python 3.11 locally** — CLAUDE.md/spec call for 3.10 or 3.12 (ZeroGPU constraint). Local `.venv` is 3.11, fine for dev; the Space must pin 3.10/3.12.
- **[phase 1] LLM backend changed from Gemini/Groq → Hugging Face Inference Providers** — per user request (one HF account, `hf` CLI already in use). `expand()` uses `huggingface_hub.InferenceClient.chat_completion` with strict `json_schema` `response_format`. Trade-off accepted: HF free tier is only ~$0.10/month of inference credit (vs Gemini's 250 req/day / Groq's 14.4k req/day permanent free) — OK for a light demo, thin provider seam kept in `expand()` for a later swap. `.env` now needs `HF_TOKEN` instead of `GEMINI_API_KEY`/`GROQ_API_KEY`.
- **[phase 1] Strict json_schema not usable on the free router by default** — live test showed `provider="auto"` routes `meta-llama/Llama-3.1-8B-Instruct` to a provider that returns `405 "json_schema response format is not supported"`. Resolution: default `LLM_STRUCTURED=object` (`{"type": "json_object"}`, widely supported) with the schema shape + an example in the system prompt, Pydantic validation, and a repair retry. `_chat()` auto-downgrades `schema → object → none` if a provider rejects the requested `response_format`. `LLM_STRUCTURED=schema` remains available for providers that support strict mode. Output quality with `json_object` + the example prompt is good (verified manually on 4 prompts).
- **[phase 1] Default LLM = `groq` + `openai/gpt-oss-20b`** — latency probe across HF router providers: `auto`→Llama-3.1-8B ~4.6 s, `groq`→gpt-oss-20b ~1 s (valid JSON, small model, light on the $0.10/mo credit). `provider="auto"` kept as documented fallback.
- **[phase 3] HF Inference free credit depleted → Groq's own API is now the primary backend** — dev iteration exhausted the ~$0.10/month HF credit (`402 "You have depleted your monthly included credits"`). Added `_GroqClient` (adapts `groq.Groq` to the `.chat_completion` surface) as backend #1 in `_default_client`; HF Inference Providers drops to fallback (used only if `GROQ_API_KEY` is unset). Groq's own free tier is 14,400 req/day, no card. Default Groq model `qwen/qwen3.8-27b` — ~0.5 s/call, 3/3 valid JSON in a reliability probe (`openai/gpt-oss-20b` and `qwen/qwen3.6-27b` both flaked with `json_validate_failed`; `_is_response_format_error` now catches that and downgrades). `.env` / `.env.example` restructured (Groq primary); `groq` + `python-dotenv` added to requirements; `app.py` and the pipeline CLI call `load_dotenv()`.
- **[phase 3] Empty env vars in `.env` were overriding code defaults** — `load_dotenv()` loads `LLM_STRUCTURED=` (blank) as `""`, and `os.environ.get(k, DEFAULT)` then returns `""`. Fixed: `... or DEFAULT` reads throughout `prompt_expand` / `pipeline`, and the optional lines in `.env`/`.env.example` are commented out rather than left blank.
- **[phase 2] AnimateLCM LoRA must be FUSED, not kept as live peft layers** — with `load_lora_weights` + `set_adapters` (live peft adapters), one denoise step took ~15 min on MPS and drove 34 GB of swap: peft's adapter forward path hits ops that fall back to CPU, ping-ponging the whole model GPU↔CPU every step. Fix in `_get_pipe`: `load_lora_weights` → `fuse_lora(lora_scale=0.8)` → `unload_lora_weights()`, so the fused model has the Phase-0 shape with LCM baked in and no adapter overhead.
- **[phase 2] Local real-render checkpoint deferred to ZeroGPU (user decision, 2026-09-07)** — after the peft swap storm the dev Mac was memory-starved. Phase 2 accepted on: code complete + 8 mocked unit tests + Phase 0's proven Route-A local render. The `python -m src.pipeline` real render is not run locally; first real render happens on the HF Space in Phase 4. Phase 3 is likewise built/tested with generation stubbed locally.
- **[phase 2] `CLIP_FRAMES` env override added** — not in the spec draft; lets the local checkpoint pin a small frame count instead of the `seconds → frames` result.
- **[phase 2] `peft` added to requirements** — needed for `load_lora_weights` even though the LoRA is fused and unloaded immediately after.
- **[phase 4] Deploy clean; cold-start render ~26 s** — `@spaces.GPU(duration=120)` left as-is. HF Xet CDN pulled the 5.5 GB model at ~1.4 GB/s; 6 LCM steps ~1.7 s on the RTX Pro 6000. Warm golden-eval renders ~5 s each.
- **[phase 4] `gradio_client` kwarg is `token=`, not `hf_token=`** — fixed in `evals/run_golden.py`. `transformers 5.16.1` on the Space (vs local 4.x) — no issues.
- **[phase 4] Golden eval: 10/10 clips, 3 first-frames read weak** — `action-01` too dark, `landscape-01` missing the "city", `mecha-01` doesn't resolve as a robot. AnimateDiff + LCM at low guidance muddies darks / vague shapes. v1 known-limitation; tunable later via guidance / steps / a brighter negative prompt. Anime style consistent across all 10.

**release-qa findings (independent Verify pass):**

- **[verify] CI gate was a no-op** — `.github/workflows/ci.yml` ran `pytest -q || (… exit 0)` and installed only `pytest pydantic python-dotenv`, so it collected zero tests (`test_app.py` needs `gradio`+`spaces`, `test_pipeline.py` needs `torch`) and passed green regardless. Scaffold placeholder never updated after Phase 1. Fixed in Ship: installs cpu-torch + `requirements-dev.txt`, runs bare `pytest` (non-zero on failure). Simulated on a fresh clone: 65 passed / 2 skipped / exit 0.
- **[verify] `app.py` seed coercion unguarded** — ticking "use fixed seed" with an empty Seed field made `int(seed)` raise an uncaught `TypeError` → stack trace instead of a friendly message. Fixed: falls back to a random seed.
- **[verify] `expand()` didn't handle `message.content = None`** — a provider returning null content raised a raw `TypeError` from `model_validate_json(None)`, bypassing the repair retry. Fixed: `_chat(...) or ""`.
- **[verify] "Generate button disabled while running"** (spec Phase 3) is delegated to Gradio's implicit queue/loading behavior, not an explicit `interactive=False` toggle. Accepted as-is.
- **[verify] `_prompt_table` shows the LLM's raw `negative_prompt`**, not the `SAFETY_NEGATIVE`-merged string actually sent to the model. Cosmetic; accepted.
- **[verify] Recommendations, not blockers:** pin `diffusers` / `transformers` in `requirements.txt` (transformers already unpinned on 5.x); Space card title vs in-app title mismatch; no output-side content check (input denylist only — deferred per framework §12); `>77`-token CLIP truncation; lazy pipeline load inside `@spaces.GPU` works but eager module-scope `.to("cuda")` is the sturdier ZeroGPU pattern.
